=====================================================================
FIX 1: Liquidation-aware exit (replaces the current stop-loss)
=====================================================================

PROBLEM
- Bybit merges multiple entries on the same symbol into ONE real 
  position with ONE averaged entry price (One-Way mode). 
  core/bybit.py's get_positions() already returns a native "liqPrice" 
  field per position from Bybit's API — no new API call needed, just 
  read that field.
- The current stop-loss (STOP_LOSS_PCT, default 80) checks each 
  individual LOT's own entry price separately, and 80% is far beyond 
  where 3x leverage actually liquidates (~30-33% price move). This 
  means it doesn't match Bybit's real merged position once multiple 
  lots exist on a symbol, and 80% is functionally unreachable — real 
  Bybit liquidation always happens first.

BUILD
1. config.py + .env.example: add LIQUIDATION_BUFFER_PCT (default 30) — 
   the % of the cushion between merged average entry price and the 
   liquidation price that must remain UNUSED before force-closing. 
   Formula (long positions):
     exit_price = liq_price + (LIQUIDATION_BUFFER_PCT / 100) * (avg_entry_price - liq_price)
   Trigger when current price <= exit_price.
   Keep STOP_LOSS_PCT parseable in config.py for backward compatibility 
   but mark deprecated in .env.example and stop using it for this 
   decision.

2. core/bybit.py: 
   - Parse and expose "liqPrice" from get_positions() results 
     alongside existing fields (avgPrice, size, etc.).
   - In set_leverage(), explicitly pass tradeMode=1 (isolated) so 
     isolated margin is enforced by code, not only manual dashboard 
     setting.

3. core/engine.py: 
   - Remove the current per-lot loss_pct / STOP_LOSS_PCT check 
     entirely.
   - Add ONE per-symbol check using that symbol's real merged position 
     (average entry price + live liqPrice from get_positions()). Do 
     NOT check individual lots.
   - If current price <= exit_price, close the ENTIRE merged quantity 
     for that symbol in a single order — not lot by lot.
   - Log as a distinct event type: 'LIQUIDATION_BUFFER_EXIT', separate 
     from the existing profitable-exit event, with a distinct Telegram 
     alert.
   - The existing profitable-exit path (RSI>=75, net PnL>0) remains 
     completely unchanged and independent.

4. backtest.py: 
   - Estimate liquidation price using the symbol's MERGED 
     weighted-average entry price across all open lots (reuse existing 
     averaging logic, don't duplicate it):
       estimated_liq_price = avg_entry_price * (1 - 1/LEVERAGE + MAINTENANCE_MARGIN_RATE)
   - Add MAINTENANCE_MARGIN_RATE as a config constant, default 0.005 
     (0.5%).
   - Apply the same exit_price formula and trigger as #3 — close the 
     ENTIRE merged lot quantity at once, not lot by lot.
   - Keep this formula in one shared/reusable location so 
     core/engine.py and backtest.py can't drift apart — follow the 
     same pattern used for the existing MAX_ACCOUNT_EXPOSURE_USDT fix.

FIX 2: Per-symbol entry cap
=====================================================================

CONTEXT
MAX_LONG_ENTRIES exists in config.py (default 999) but isn't enforced 
as a real per-symbol limiter — a symbol can currently accumulate many 
stacked lots (seen up to 8+ in backtests) before any other cap stops 
it. This matters more now given Fix 1 closes ALL lots on a symbol 
together — I want to also cap how large that merged position can get 
in the first place.

BUILD
1. Set MAX_LONG_ENTRIES default to 5 in config.py / .env.example.
2. core/engine.py: before allowing a new entry, count current open 
   lots for that symbol. If >= MAX_LONG_ENTRIES, block the entry, log 
   a RISK_BLOCK event (reason: 'max_long_entries_per_symbol') — same 
   style as the existing MAX_ACCOUNT_EXPOSURE_USDT block logging.
3. backtest.py: apply the identical per-symbol lot-count check before 
   allowing a new entry, so backtest and live stay aligned.
4. This check runs BEFORE the exposure-cap and margin checks (cheapest 
   check first) but doesn't replace them — an entry must pass both 
   independently.
